# 使用手册 · Paper2Play

读到 Logistic 增长方程，却想不清参数会怎样影响曲线？把原文放在左边，在右边动手调一调，公式、来源和结果就能对照着看。

![Paper2Play 研究笔记：左侧为示例原文，右侧为公式、曲线与参数](../docs/images/notebook.png)

适合正在学增长模型的学生，也适合备课时想演示“增长速率”和“环境容量”区别的老师。它目前只做这一个方程：`P(t)=K/(1+A*exp(-r*t))`。不需要账户或 API Key。

## 先试一次

1. 点击 **载入示例**。这是项目自编的资料，界面会明确标注，不是一篇真实论文。
2. 把 **r 增长速率**从 0.30 调到 0.60。P(10) 从 69.057 变成 97.818；再把 **K 环境容量**调到 150，P(10) 变成 146.727。
3. 点击 **查看来源**，对照原文。鼠标悬停曲线可以读数；Tab 切换控件，方向键微调参数。

下图是第二步完成后的实际计算结果，A 保持为 9：

![K 为 150、A 为 9、r 为 0.60 时的曲线，P(10) 为 146.727](../docs/images/experiment.png)

也可以粘贴包含该表达式的文字，或上传含文字的 PDF。仓库里的 [示例 PDF](../fixtures/logistic.pdf) 把公式放在第 2 页，可以用它检查提取结果和页码。输入 `E=mc²` 会提示暂不支持，不会生成一条猜测的曲线。

## 在本机启动

需要 Node.js **`^22.13.0 || ^24.0.0 || >=26.0.0`**，推荐 **24 LTS**。锁定的 Vitest 不支持 Node 23 / 25，PDF.js 要求 Node 22 至少为 22.13；setup 和 doctor 使用同一规则检查。

在本项目目录执行：

```sh
npm ci --cache .npm-cache
npm run dev
```

打开 [127.0.0.1:4209](http://127.0.0.1:4209)。网页和 API 会一起启动，API 使用 5209 端口；两者只监听本机。不需要 `.env` 或模型凭据。

要安装自动化测试用的浏览器并检查环境：

```sh
npm run setup
npm run doctor
```

`setup` 安装锁定依赖、Chromium 和 FFmpeg，缓存放在项目的 `.npm-cache/` 与 `.browsers/`，不会安装系统组件。若已经装好 npm 依赖，可单独运行 `npm run browsers:install`。doctor 会检查 Node、依赖、浏览器启动、录屏编码器和端口；缺少浏览器只影响自动化测试，不妨碍手动使用网页。

如果浏览器下载失败，可以重试安装，或用 `PLAYWRIGHT_EXECUTABLE_PATH` 指向已有的 Chromium 可执行文件；`PLAYWRIGHT_BROWSERS_PATH` 可指定匹配的浏览器缓存目录。默认使用项目内缓存。本次验证复用了这台 Mac 上的 Chromium 和项目内 FFmpeg，没有重新做空缓存下载。

端口被占用时，先停止自己已启动的那一份应用再试。网页提示连接失败时，检查运行 `npm run dev` 的终端，以及 [API 健康检查](http://127.0.0.1:5209/api/health)。脚本不会替你结束其他进程或改变端口。

## 它现在能做到哪里

- **识别范围很窄。** 只匹配预设 Logistic 文字表达式，忽略大小写、空白和 Unicode 减号差异。不理解任意等价式、LaTeX 或其他方程，也不验证文献的科学结论。
- **没有调用 AI。** 曲线来自固定数值函数，每次调整计算 101 个点。默认 K=100、A=9、r=0.3 是演示参数，不是从论文里估计出来的。项目仍标记为 PARTIAL，尚未实现通用论文转实验。
- **PDF 必须有文字。** 不支持 OCR；最多 5 MB、40 页，提取超时 15 秒，同一时间处理一个文件。粘贴文本最多 50,000 字符。复杂 PDF 仍可能消耗较多内存。
- **内容留在本机。** 上传文字只在进程内存中处理，不保存到磁盘、不发给远程服务。不执行用户公式代码，没有任意文件读取或 URL 抓取接口。本地服务没有鉴权，不适合直接暴露到公网。

## 验证与开发

React / TypeScript 构建界面，Express 处理提取，PDF.js 按页读取文字，Recharts 绘制计算结果。没有字体 CDN 或其他页面资源请求。

```sh
npm run doctor
npm run build
npm run test
npm run e2e
npm run demo
```

本轮在 macOS、Node 26.4.0 和 Chromium 上验证：24 项单元测试、7 项浏览器测试、1 项独立演示测试通过。浏览器测试会自动启动应用，请先保持 4209 / 5209 空闲。

测试覆盖真实 PDF 第 2 页提取、不支持的输入、文件大小限制、参数与读数一致性、1440×900 和 390 像素宽布局、键盘焦点、加载提示、连接失败与重试。README 两张图片由 `tests/demo.spec.ts` 实际操作后拍摄，已保存在仓库的 `docs/images/`；本地录像位于 `artifacts/playwright/demo/`，日志位于 `artifacts/logs/redesign-*.log`，结果见 [status.json](../status.json)。

构建仍有非致命的包体积提示。Windows、Linux、其他浏览器和正式无障碍认证尚未验证；Node 版本边界有自动测试，但没有逐版本安装运行。
